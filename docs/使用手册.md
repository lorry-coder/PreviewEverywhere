# PreviewEverywhere 使用手册

一个跑在你开发机上的常驻小服务。它盯着你的项目目录，agent 每写出一份 md / html
就自动收进来、渲染好、建好索引；你在手机上打开就能读、能划重点、能搜。

整个平台是**一个可执行文件**，没有运行时依赖。数据全在一个目录里，删掉就是彻底重置。

---

## 一、五分钟跑起来

```bash
cd PreviewEverywhere
make build                       # 构建前端并嵌进二进制，产出 ./pe

./pe watch add ~/你的项目/docs     # 告诉它盯哪儿
./pe serve                       # 启动
```

终端会打印这样一段：

```
  PreviewEverywhere 已启动

    http://192.168.31.10:8080
    http://172.17.0.1:8080
    http://127.0.0.1:8080

  首次启动，用手机扫码登录（有效期一年）：

  ████████████████████
  ██ ▄▄▄▄▄ █▀▄█ ▄▄▄▄▄ ██
  …（二维码）…

  口令: 2ed1479bca1fe700f9a218ba8092017a…
  这串东西只显示这一次，但随时可以用 `pe token` 换新的。
```

**手机连同一个 Wi-Fi，直接扫码**，扫完就进去了，一年内不用再输任何东西。
电脑上开列出的任意一个地址，把口令粘进登录框。

> 二维码只在**第一次启动**（还没有口令时）出现。之后想再扫一次，跑 `./pe token`
> 生成新口令并重新打印。注意：**换完口令要重启 `pe serve` 才生效**，
> 重启后所有设备的旧登录一并失效。详见第二节「口令与多设备」。

## 二、访问路径

### 从哪打开

| 场景 | 地址 |
|---|---|
| 本机 | `http://127.0.0.1:8080` |
| 局域网内的手机 / 平板 / 另一台电脑 | `http://<开发机的局域网IP>:8080`（启动时列出来了） |
| 不在同一个网络 | 装 [Tailscale](https://tailscale.com)，用 tailnet 地址访问 |

监听地址默认是 `0.0.0.0:8080`（所有网卡）。改端口：

```bash
./pe serve --bind 0.0.0.0:9000
```

或写进配置文件（见第六节），这样不用每次带参数。

> **不要把这个端口转发到公网。** 它是单用户、口令鉴权、局域网用的。
> 要远程访问就用 Tailscale，那样不必开任何入站端口。

### 口令与多设备

**一个口令走天下，设备数量没有上限。** 手机、平板、另一台电脑可以拿同一个口令同时登录、
同时使用——实测三台并发访问全部正常。扫码登录后种下的 Cookie 有效期一年，
扫一次就长期不用再管。

理解下面这些行为，关键是知道**平台没有会话机制**：Cookie 里存的就是口令本身，
服务端每次请求拿它跟配置里的哈希比一次。由此推出三条：

- **不需要管理 token。** 不存在「多个 token」，只有「口令的当前值」这一个东西。
  没有 token 列表，也没有过期策略。
- **没法单独踢掉某一台设备。** 手机丢了，唯一的办法是换口令——然后所有设备一起掉线，
  都要重新扫码。
- **换口令必须重启 `pe serve` 才生效。** 服务端启动时把口令哈希读进了内存，
  之后不再重读配置文件。

所以 `pe token` 的完整流程是：

```bash
./pe token                    # 生成新口令并打印二维码
# 此刻：新口令还是 401，旧口令仍然有效
systemctl --user restart pe   # 或者 Ctrl-C 后重新 ./pe serve
# 重启后：新口令生效，所有设备的旧 Cookie 一起失效
```

> 这是单用户设计的直接后果：阅读状态和批注都没有归属人，几台设备看到的是**同一份**
> 已读状态、**同一批**批注。它适合「你一个人在几台设备之间切换」，不适合多人共用。

### 加到手机主屏

平台是 PWA。手机浏览器打开后：

- **iOS Safari**：分享 → 添加到主屏幕
- **Android Chrome**：菜单 → 添加到主屏幕 / 安装应用

加完之后它像个独立应用一样打开，没有浏览器地址栏，**并且能离线读**——
之前打开过的文档、图片、你划的重点，断网时都还在。搜索和推送需要联网。

### 界面上有哪些页面

地址栏里的 `#/…` 就是页面路径，可以直接收藏或分享。

| 页面 | 地址 | 作用 |
|---|---|---|
| 时间线（首页） | `#/` | 按 agent 会话或「日期 + 项目」分组，看「昨晚那次跑出了什么」 |
| 全部文档 | `#/all` | 按更新时间倒序的平铺列表 |
| 未读 | `#/unread` | 只看没读过的 |
| 稍后读 | `#/later` | 手动标记「等有整块时间再看」的 |
| 待办与疑问 | `#/todo` | 所有文档里标的待办和疑问汇总成一张清单 |
| 某个项目 | `#/project/<id>` | 侧栏点项目名进入 |
| 某个标签 | `#/tag/<标签名>` | 侧栏点标签，或点文档上的标签 |
| 搜索 | `#/search/<关键词>` | 顶栏搜索框，⌘K / Ctrl-K 聚焦 |
| 阅读页 | `#/doc/<id>` | 单篇文档 |

阅读页在宽屏上是三栏：左侧项目与标签，中间正文（720px 居中），右侧大纲与批注。
窄屏自动收起两侧，左上角 ☰ 打开导航。

## 三、把文档送进来的四种方式

| 方式 | 适合 | 要不要配置 | agent 要不要改 |
|---|---|---|---|
| **文件监听** | 文档固定放在某些目录 | 加一次监听目录 | 不用 |
| **Claude Code hook** | 文档到处都是（推荐） | 装一次 hook + **配客户端口令** | 不用 |
| **命令行推送** | 偶尔手动推一篇、跨机器 | **配客户端口令** | 不用 |
| **MCP** | 让 agent 自己决定「这份值得给人看」 | 配 MCP + **客户端口令** | 会主动调用 |

四条通道进平台之后走的是同一条管线，区别只在元数据从哪来。

> **后三条都要配 `~/.config/pe/config.toml`**（客户端配置），因为它们都是 HTTP 客户端，
> 要知道往哪发、拿什么口令。这份文件和服务端的 `pe.toml` 是**两份不同的文件**，
> 别搞混（见第六节）。`endpoint` 有默认值 `http://127.0.0.1:8080` 可以不写，
> **但 `token` 没有默认值，必须配**；也可以改用 `PE_ENDPOINT` / `PE_TOKEN` 环境变量。
>
> **文件监听不需要任何客户端配置**——它是服务端自己在读盘，不走 HTTP。

### 1 · 文件监听

```bash
./pe watch add ~/项目/docs              # 单个目录
./pe watch add '~/Code/*/docs'          # 通配符，引号不能省
./pe watch add '~/Code/*' --include '*报告*.md' --include '*分析*.md'
./pe watch list                         # 看现在监听了哪些
./pe watch rm ~/项目/docs
```

改完要**重启 `pe serve`** 才生效。

> **通配符一定要加引号。** 不加的话 shell 会先替你展开：匹配到多个目录时直接报用法
> 错误；只匹配到一个目录时会**静默成功**——你以为配了通配符，实际只钉死了那一个目录，
> 以后新建的目录再也进不来。加了引号才是把通配符存进配置、由服务端在运行时展开，
> 而且每 30 秒重新展开一次，之后新建的匹配目录会自动纳入。
> 拿不准就 `./pe watch list` 看一眼存进去的是通配符还是一个具体路径。

默认只收 `*.md`、`*.markdown`、`*.html`、`*.htm`，并且跳过 `node_modules`、`.git`、
`dist`、`3rdparty` 这类目录（完整列表见 `pe.toml` 的 `ignore`）。此外**含
`CMakeCache.txt` / `build.ninja` 的目录会整棵跳过**——构建树的名字千奇百怪
（`build_rerun`、`out-arm64`），认标记文件比认名字可靠，否则里面几百页 doxygen
自动生成的 HTML 会把你真正要读的东西挤到后面。

`watch add` 会当场数一遍需要监听多少子目录并和本机预算对比，超了才需要动手收窄：

```console
$ ./pe watch add ~/Code/CXX
已添加监听: /home/you/Code/CXX
重启 pe serve 后生效。
需监听约 3235 个子目录（已扣除忽略规则），本机预算 32768。
```

**文档归到哪个项目**：从文件位置向上找——先找 `.pe.toml`，再找 `.git`，
都没有就往上取第一个不是 `docs` / `source` / `notes` 这类通用名的目录名。
想固定死就 `--project 名称`，或在文档的 front-matter 里写 `project:`。

#### 文件改了、删了、改名了，库里会怎样

| 你的操作 | 平台的反应 |
|---|---|
| 改内容 | 版本号 +1（v1 → v2），旧版本保留，**重新变成未读** |
| 原样重写、内容没变 | **什么都不做**，不产生新版本 |
| 新增文件 | 作为新文档收进来，v1 |
| **删除文件** | **库里原样保留**，文档不会消失 |
| **改名文件** | 同一篇**跟着改名**，批注、标签、已读状态、版本历史全部原地保留 |

几件值得知道的事：

- **旧版本不会丢。** 每次内容变化都存一份新版本，阅读页可以看版本之间的 diff。
  挂在上面的批注会自动跟过去：段落没变的直接命中，段落改过的用模糊匹配找回并标记为
  「已移动」，实在找不到的变成孤儿等你手动重挂，**不会被删掉**。
- **内容不变就完全跳过**，靠内容哈希比对。agent 反复写同一份文件是常态，
  这条判断挡掉了绝大部分无效工作。
- **删除源文件是故意不处理的。** 平台是文件系统的下游：源文件被清理了，你读过、
  标注过的东西不该跟着消失。要真的删掉某篇，在阅读页点「删除」（见下）。
- **改名靠内容识别，不靠文件系统事件。** 改名在事件里就是「删旧 + 建新」，
  平台的判据是「内容哈希一致 + 旧路径已不在磁盘上 + 新路径尚未入库」三条同时成立。
  所以 `cp a.md b.md` 会得到两篇（原文件还在），而 `mv` 会跟着走。
  **同时改名又改内容则认不出来**，会当成新文档收进来——这种情况只能手动删掉旧的那篇。
- **完整扫描只在启动时做一次。** 服务停着的时候你改的文件，要等下次 `pe serve`
  才会被发现。这也是为什么 NFS / SMB 挂载的目录不适合监听——它们根本不产生文件事件，
  等于只有重启才同步一次。

#### 删掉一篇文档

阅读页右上角的「删除」。二次确认里会告诉你有多少条批注会一起消失——
批注和版本历史是这个平台里**唯一无法从别处恢复**的东西，源文件还能重新采集，
你写的批注不能。磁盘上的源文件不受影响。

默认会记住「这篇不要了」。**这一条很关键**：源文件多半还在被监听的目录里，
不记的话下次启动扫描原样收回，删除就成了一个假动作。确认框里可以勾掉，
表示「以后它再被扫到时我还想要」。

记住之后有一个例外：**显式 `pe push` 同一个文件会覆盖它**，重新收进来。
自动通道（监听、hook）尊重「我删过它」，你亲手推的则不。
理由是后者更能代表当下的意图。

### 2 · Claude Code hook（推荐）

装上之后 agent 每写一个 md / html 就自动进平台，**不管它写在哪个目录**，
同一次会话的产出还会在时间线上聚成一组。

```bash
# ① 先配客户端口令（见第六节），否则 hook 会静默跳过
mkdir -p ~/.config/pe
cat > ~/.config/pe/config.toml <<EOF
endpoint = "http://127.0.0.1:8080"
token = "<pe serve 或 pe token 打印的那串口令>"
EOF

# ② 装 hook
./pe hook-install            # 只打印配置片段，你自己粘
./pe hook-install --write    # 直接写进 ~/.claude/settings.json（会先备份 .bak）
```

装完**重开一个 Claude Code 会话**才生效。

**它是怎么触发的**：`hook-install` 写进 `~/.claude/settings.json` 的是一条
`PostToolUse` 钩子，matcher 为 `Write|Edit`。agent 每完成一次写文件，Claude Code
就把一段 JSON 从 stdin 喂给 `pe hook-ingest`，然后依次判断：

1. 从 payload 里取文件路径（依次试 `file_path` / `notebook_path` / `path` 几个字段），
   相对路径用 payload 里的 `cwd` 补成绝对路径
2. 扩展名不是 `.md` / `.markdown` / `.html` / `.htm` → 跳过
3. 路径里含忽略目录，或落在构建树（含 `CMakeCache.txt` 等标记文件的目录）内 → 跳过
4. 文件不存在、或那是个目录 → 跳过
5. 没配客户端口令 → 跳过
6. 推送，并带上 `session_id`——**同一次 agent 会话的产出会在时间线上聚成一组**

第 2、3 步用的是和文件监听完全相同的判断规则，所以两条通道不会出现
「监听不收、hook 却收了」的分歧。区别在于 hook 拿不到服务端的 `pe.toml`
（服务端可能在另一台机器上），只能用内置的忽略规则，你在 `pe.toml` 里自己加的那几条
对 hook 不生效。

> hook 的设计原则是**绝不打断 agent**：平台没起、口令没配、网络不通，它都静默退出，
> 不会让你的 agent 报错或卡住。代价是出问题时没有任何提示。
> 排查用：
> ```bash
> echo '{"cwd":"/x","tool_input":{"file_path":"/x/某文件.md"}}' | ./pe hook-ingest --verbose
> ```

### 3 · 命令行推送

同样需要先配 `~/.config/pe/config.toml`（或设 `PE_ENDPOINT` / `PE_TOKEN` 环境变量）。

```bash
./pe push 报告.md --tag 风险 --tag 待复核
./pe push 报告.md --project 支付重构 --title "改个标题"
cat 结论.md | ./pe push - --run "$SESSION"     # 管道推送
```

跨机器就把 `endpoint` 改成服务器的地址。两种情况文档里引用的图片都会跟着走：
同机时给的是文件路径，服务端自己去读；跨机时客户端把被引用的图片一起打包发过去
（单张上限 2 MB，越界引用一律拒绝）。

### 4 · MCP

```bash
./pe mcp     # stdio MCP server，由 agent 客户端拉起
```

它向 agent 暴露一个 `publish_document` 工具，让 agent 在长任务结束时主动投递一份
带标题、标签和摘要的总结——和 hook 的区别是「主动 vs 被动」：hook 把每个 md 都收
进来留档，MCP 让 agent 自己挑值得给人看的。

### 让 agent 顺手带上元数据

在文档开头写几行 front-matter，就免掉了后续所有手动归类。渲染时会自动剥掉，不污染正文：

```markdown
---
title: 迁移风险评估
project: auth-refactor
tags: [风险, 待复核]
summary: 双写窗口期是主要风险来源
---
```

`summary` 会显示在列表里，让你一眼判断值不值得点开。
值得把这条写进项目的 `CLAUDE.md`：「生成报告类文档时，在开头加 front-matter 注明
project 和 tags」。

## 四、日常怎么用

### 读

- **未读圆点**：新收进来的文档标未读；滚到底或停留够久自动标已读，也可以手动点「标为已读」。
- **稍后读**：这篇要认真看但现在没时间，点一下进队列，侧栏「稍后读」里找。
- **阅读进度跨设备同步**：电脑上读到一半，手机打开自动回到那里。
- **版本变化**：agent 重跑一次会产生新版本（标题旁显示 `v2`、`v3`）。
  正文上方会告诉你「相比 v1：3 段有变化」，点「只看变化」就只剩改动的段落，
  不必从头再读一遍。

### 划重点与做笔记

在正文里**选中一段文字**（手机上长按取词），弹出气泡，四种类型：

| 类型 | 用来 |
|---|---|
| 高亮 | 单纯标出来 |
| 笔记 | 写点想法 |
| 待办 | 要去改的事 |
| 疑问 | 要去确认的事 |

**待办和疑问会汇总到 `#/todo`**，跨所有文档一张清单，可以一键复制成 Markdown，
直接粘给下一轮 agent 当输入——这是「在通勤路上读文档」的产出物。

**agent 重写文档之后批注怎么办**：没动过的段落上的批注原样保留；段落被改写但那句话
还在的，自动迁移过去并打「已自动重定位」角标提示你复核一眼；原文真的没了的进
右栏「失联批注」，**内容不删**，保留当初的原文快照，可以手动重挂到新位置。

### 看回去、改、删

**点一下正文里的高亮**，会弹出这条批注的卡片：当初写的内容、类型、原文引用，
以及「编辑」和「删除」。手机上这是唯一的入口——右栏（大纲 + 批注列表）
在窄屏下是隐藏的。

正文末尾还有「我的批注（N）」，展开是这篇文档的全部批注，点任意一条会滚到
它在正文里的位置。「目录」也在同一处。

**待办与疑问页**的每一条右侧有「完成并删除」。做完的事要能划掉，
否则这张清单只进不出。

### 把一篇带走

阅读页操作区的**分享**，三条路：

| 方式 | 得到什么 | 什么时候用 |
|---|---|---|
| **导出单文件 HTML** | 图片、公式、图表全内联进一个 `.html` | 发给别人看。双击就开，离线也能看，不依赖任何平台 |
| **打印 / 存为 PDF** | 系统打印面板，可存成 PDF | 对方习惯 PDF，或者要打出来 |
| **下载原始文件** | 原文一字未改；带图片时打包成 `.zip` | 拿回源码喂给下一轮 agent |

单文件 HTML 是在**浏览器里**生成的，因为只有那里才有已经渲染好的图表和公式——
服务端只有一份还没执行过 JS 的 HTML，导出去图表就只剩一段代码。生成后交给
服务端换一个下载链接，是因为 iOS Safari 对 `<a download>` 的支持时好时坏，
而「真实地址 + `Content-Disposition`」一直可靠。

> **为什么没有「系统分享面板」**：`navigator.share` 和剪贴板一样需要安全上下文，
> 而局域网是 http，那里它根本不存在。所以分享只能先下载成文件，
> 再从系统的文件应用里分享出去。

zip 里的 md 是**一字未改**的原文，图片按原始相对路径放回去（`./img/arch.png`
还在 `img/arch.png`），所以解开就能直接用。个别用 `../` 逃出目录的引用没法安全
放进压缩包，会落到 `_assets/` 并在包内的说明文件里注明。

> **老文档可能拿不到图片。** 「文档里的路径 → 库里的图片」这层对应关系是后来才
> 开始记录的。对更早入库的文档，程序会用当初生成 HTML 的同一个解析器按出现次序
> 配对，并且**要求两边数量完全相等**才配；对不上就不猜，只打包 md 并在
> `图片说明.txt` 里说明原因——一张配错的图比一张缺失的图更糟，因为它看起来是对的。
> 把文档重新采集一次（碰一下源文件即可），这条限制就不存在了。

### 搜索

顶栏搜索框，⌘K / Ctrl-K 聚焦。支持组合语法：

```
迁移风险                 全文
"双写窗口期"              整段短语（引号内不拆词）
tag:待复核               带某个标签
tag:风险 -tag:已解决      组合与排除
project:auth 双写        在某个项目里搜
is:unread                只看未读（还有 is:read、is:later）
kind:html                只看 HTML 文档
```

字段名也认中文：`标签:` `项目:` `状态:`。搜索框留空时会列出这些语法，
点任意一行直接试用。

> 中文三字以上的词走索引，两字词（如「双写」）走全表匹配——**两种都能搜到**，
> 只是后者在文档量非常大时会慢一些。

### 标签

阅读页标题下方点 `+ 标签` 添加，点标签上的 `×` 删除。
删掉一个来自 front-matter 的标签之后，agent 重新生成同一份文档**不会**把它加回来——
否则手动整理标签就是白干。

## 五、数据保存在哪

**全部数据在一个目录里：`~/.local/share/pe/`**

```
~/.local/share/pe/
├── pe.db            SQLite 数据库：文档、版本、标签、批注、检索索引
├── pe.db-wal        SQLite 的预写日志（运行时存在，含尚未合并的最新写入）
├── pe.db-shm        SQLite 的共享内存索引（运行时存在）
├── pe.toml          服务端配置：监听目录、忽略规则、口令哈希
└── blobs/           原始文件与图片，按内容哈希两级分片存放
    └── 8f/4f/8f4fd4c9bca8…
```

改位置：`./pe serve --data /别的/路径`，或设环境变量 `PE_DATA_DIR`。

**它不会在你的项目目录里留任何东西。** 原始文件会被复制一份进 `blobs/`，
所以 agent 删了中间产物、你切了分支，手机上照样读得到。

### 占多少空间

文本文档的体积可以忽略；主要占用来自图片和 agent HTML 里内联的图表库。
每个文档版本都会留一份，所以反复重跑的文档会累积。目前**没有自动清理**，
需要时手动看：

```bash
du -sh ~/.local/share/pe/
du -sh ~/.local/share/pe/blobs/
```

### 备份

没有内置的备份命令。停掉服务再打包整个目录即可：

```bash
# 停掉服务（Ctrl-C，或 systemctl --user stop pe）
tar czf pe-backup-$(date +%F).tar.gz -C ~/.local/share pe
```

> **运行中直接拷贝 `pe.db` 是不安全的**——最近的写入还在 `pe.db-wal` 里。
> 要么停服务，要么三个 `pe.db*` 文件连同 `blobs/` 一起拷。

### 换一台机器

把整个 `~/.local/share/pe/` 目录拷过去，再拷一个 `pe` 二进制（或在新机器上
`make build`）。`pe.toml` 里的监听路径是绝对路径，新机器上目录结构不同的话要改。

### 彻底重置

```bash
rm -rf ~/.local/share/pe
```

下次 `pe serve` 会当作全新安装：重建数据库、生成新口令、打印新二维码。

## 六、配置文件

### 服务端：`~/.local/share/pe/pe.toml`

`pe watch add` / `pe token` 会自动改它，也可以手编。改完要重启 `pe serve`。

| 项 | 默认 | 说明 |
|---|---|---|
| `bind` | `"0.0.0.0:8080"` | 监听地址与端口 |
| `token_hash` | 自动生成 | 访问口令的 sha256。口令本身不落盘，忘了就 `pe token` 换新的 |
| `ignore` | 见下 | 永不采集的目录名 |
| `localize_cdn` | `true` | 入库时把 agent HTML 引用的 CDN 图表库抓下来内联，离线也能看图。设 `false` 则入库过程完全不联网 |
| `[[watch]]` | 无 | 监听规则，可多条 |

`ignore` 分四类：版本控制与编辑器（`.git` `.idea` …）、依赖（`node_modules`
`vendor` `.venv` …）、构建产物（`dist` `build` `release` `Debug` `cmake-build-*` …）、
vendored 第三方源码（`3rdparty` `third_party` `external` …）。完整列表看
`pe.toml`——首次启动会写进去。三条规矩：

- **支持通配符**：`build-*`、`cmake-build-*` 这种写法有效（`filepath.Match` 语义）。
- **内置规则始终生效**，即使你的 `pe.toml` 里没列。程序新增的忽略规则会自动并进
  已有配置——否则第一次保存时的那份列表会被永久冻住，以后的修复对老装机一条都不生效。
- **不想要某条内置规则**，在 `ignore` 里写 `"!external"`。比如 `external/` 在多数
  C++ 仓库里是 vendored 依赖，但你那边可能真是放文档的地方。

一条 `[[watch]]` 长这样：

```toml
[[watch]]
  path = "~/Code/*/docs"                                    # 支持通配符与 ~
  project = "固定项目名"                                     # 可选，留空自动判定
  include = ["*.md", "*.markdown", "*.html", "*.htm"]        # 可选
```

### 客户端：`~/.config/pe/config.toml`

**这是另一份文件，别和上面的 `pe.toml` 搞混。** 服务端配置说的是「我监听什么、
忽略什么」，客户端配置说的是「我往哪推、拿什么口令」。

`pe push`、`pe hook-ingest`、`pe mcp` 三条通道共用它，**不配的话推送会报错、
hook 会静默跳过**。`pe watch` 和 `pe serve` 不读它。

```toml
endpoint = "http://127.0.0.1:8080"   # 跨机器就填开发机的局域网地址
token = "<pe serve 或 pe token 打印的那串口令>"
```

`endpoint` 不写就是 `http://127.0.0.1:8080`，同机使用可以省；**`token` 没有默认值，
必须配**。环境变量 `PE_ENDPOINT` / `PE_TOKEN` 优先级更高，适合临时覆盖或写进 CI。

两份配置的对照：

| | 服务端 `~/.local/share/pe/pe.toml` | 客户端 `~/.config/pe/config.toml` |
|---|---|---|
| 谁读 | `pe serve` / `pe watch` | `pe push` / `pe hook-ingest` / `pe mcp` |
| 装在哪 | 跑服务的那台机器 | 跑 agent 的那台机器（可能是同一台） |
| 内容 | 监听目录、忽略规则、口令哈希 | 服务地址、口令明文 |
| 存不存口令原文 | 不存，只存 sha256 | 存明文（文件权限 0600） |

### 项目标记：`.pe.toml`

放在项目根目录，用来固定这个项目在平台里的显示名：

```toml
project = "支付重构"
```

## 七、部署方式

先决定一件事：**这台机器让不让你方便地跑 systemd 用户服务？**

| 环境 | 建议 |
|---|---|
| 普通 Linux 服务器、自己装系统的小主机 | 直接跑二进制 + systemd |
| 群晖 / QNAP / unRAID / TrueNAS SCALE | Docker |

这个程序本来就是「一个静态可执行文件」的形态，Docker 在它身上加的那层几乎不带来
收益；但上面那些 NAS 系统里 Docker 才是被官方支持的运行方式，硬塞 systemd 反而更脆。

### 部署到远端 = 推送模式

这一点比选哪种运行方式更重要：**你的 agent 和文件都在开发机上，远端那台机器
根本看不到那些目录。** 所以远程部署时「文件监听」这条通道基本用不上，
真正在用的是 hook 和 `pe push`——而它们一个目录挂载都不需要。

开发机上把客户端指向远端即可：

```toml
# ~/.config/pe/config.toml
endpoint = "http://<服务器或NAS的IP>:8080"
token = "<pe token 打印的口令>"
```

### 直接跑（systemd 用户服务）

不需要 root。

```bash
mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/pe.service <<EOF
[Unit]
Description=PreviewEverywhere
After=network-online.target

[Service]
Type=simple
ExecStart=$PWD/pe serve
Restart=on-failure
RestartSec=5

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now pe
loginctl enable-linger "$USER"     # 让它在你没登录时也继续跑
```

常用命令：

```bash
systemctl --user status pe
systemctl --user restart pe        # 改完 pe.toml 之后
journalctl --user -u pe -f         # 看日志
```

### Docker

仓库里有 `Dockerfile` 与 `docker-compose.yml`，默认就是推送模式——不挂任何项目目录。

```bash
docker compose up -d --build
docker compose logs -f          # 首次启动的二维码和口令在这里
```

数据在名为 `pe-data` 的卷里，那一个卷就是全部需要备份的东西。

**三件必须注意的事：**

1. **一定要设 `TZ`。** 容器默认 UTC，而时间线是按「服务端本地日期」分组的，
   界面上的「今天 / 昨天」却按你手机的时区显示——半夜前后写的文档会被归到昨天
   却标着「今天」。compose 里已经写了 `TZ: Asia/Shanghai`，改成你自己的。
2. **inotify 只在本地文件系统上可靠。** 真要在容器里监听目录，被监听的路径必须是
   这台机器的本地磁盘；如果那些目录本身是 NFS/SMB 挂进来的，文件监听不会触发，
   而且不会报错。那种情况只能用推送模式。
3. **挂载项目目录时，容器内外路径要一模一样**（`- /home/me/Code:/home/me/Code`）。
   `pe.toml` 里存的是绝对路径，两边不一致的话你在宿主机上按容器里的路径去找会对不上。
   同时用 `user: "1000:1000"` 让容器以你的 uid 跑，免得写出 root 属主的文件。

## 七点五、遇到问题怎么反馈

侧栏「诊断」组下的**问题反馈**（或 `#/feedback`）。写一句话提交即可，
程序会自动附上当时的设备环境和所在页面——这些正是事后最难补问、
又最能决定排查方向的东西。

三种状态：**待修复 / 已修复 / 无需修复**，界面上和命令行上都能改。

```bash
pe feedback                     # 默认只看待修复
pe feedback list --status all
pe feedback show 3              # 含完整环境快照
pe feedback fix 3 --note "改成三值判定后修好了"
pe feedback wontfix 3
pe feedback reopen 3
pe feedback rm 3
pe feedback export --format jsonl
```

数据目录下还有一份 **`feedback.md`**，每次变动后全量重写，打开就能看。
它是投影不是第二份数据——**直接改它不会生效**，改状态请用上面的命令或界面。

## 八、排查

### 先看「环境自查」

侧栏最下面的**环境自查**（或直接访问 `#/diag`）。手机上出问题时先开这一页——
它把开发机上复现不了的那些数字直接摆出来：

| 这一行 | 说明什么 |
|---|---|
| 前端版本（浏览器在跑 / 服务端携带） | 两个不一样就是浏览器还在用缓存里的旧界面 |
| 是否在跑旧缓存 | 上面那两行的结论。是的话点「清缓存并重载」 |
| 是否触屏 | 决定气泡要不要给 iOS 的系统选区菜单让位（手机上应当是「是」） |
| 底部被遮挡 | 浏览器地址栏或软键盘吃掉了多少高度 |
| 安全区 上/下 | 刘海与手势条的尺寸 |

页面上还有一栏**选区事件记录**：点「开始记录选区事件」，长按下面那段示例文字，
就能看到 iOS 实际发了哪些事件、每一刻选区是什么状态、气泡在不在。
划词相关的问题，把这段记录发出来比描述现象有用得多。

点「复制记录」之后，记录会**同时**摊在一个文本框里。原因是这个平台走的是
局域网 http，属于非安全上下文，浏览器根本不提供 `navigator.clipboard`；
退回老接口之后，iOS 上它「成功」了也可能压根没往剪贴板里放东西。
所以原文一定摆在那儿——长按全选，或者直接截图。「待办与疑问」页的
「复制为 Markdown」同理。

页面最下面有一条模拟的操作条。**如果它被浏览器地址栏挡住了，那就是问题所在。**

> **更新了 pe 却看不到变化？** 前端是编译进二进制的，所以顺序是
> `make build` → 重启 `pe serve` → 手机上刷新。只跑 `go build` 不会重新构建前端。
> 服务端是不是新的，看自查页的「前端版本（服务端携带）」；
> 手机是不是新的，看「浏览器在跑」那一行。

| 症状 | 多半是 | 怎么办 |
|---|---|---|
| 新写的文档不出现 | 那个目录没被监听 | `./pe watch list` 看一眼；通配符要加引号；改完要重启 `pe serve` |
| 同上 | 文件不是 md / html，或落在 `ignore` 的目录里 | 看 `pe.toml` 的 `ignore` |
| 「新文档有时候进来有时候不进来」 | inotify 句柄用尽 | 界面和日志会告警并列出最先被跳过的目录；把那些目录名加进 `ignore`，或 `sudo sysctl -w fs.inotify.max_user_watches=524288` |
| 装了 hook 但没反应 | 客户端口令没配（hook 会静默跳过） | 配 `~/.config/pe/config.toml`，再用 `hook-ingest --verbose` 看它抱怨什么 |
| 同上 | 装完没重开 Claude Code 会话 | 重开一个 |
| `pe push` 报「没有访问口令」 | 同上 | 同上 |
| Ctrl-C 退出时报 `context deadline exceeded` | SSE 是永不结束的长连接，优雅退出在等它们 | 已修：退出前先让 SSE 收尾 |
| 手机打不开 | 不在同一个 Wi-Fi，或防火墙挡了 | 先在电脑上试局域网地址；跨网络用 Tailscale |
| 登录失效、要重新输口令 | 跑过 `pe token`，旧口令作废了 | 重新扫码 |
| 跑了 `pe token`，新口令却一直 401 | 服务端还在用内存里的旧哈希 | 重启 `pe serve` |
| 点「复制」没反应 / 粘出来是空的 | 局域网 http 是非安全上下文，没有剪贴板接口 | 用按钮下面摊出来的文本框手动选，或截图 |
| 下载的 zip 里文件名是乱码 | 某些 Linux 版 `unzip` 忽略压缩包的 UTF-8 标志 | 包本身是对的；用 7z、Python 或图形界面解压即可 |
| 导出提示体积超限 | 图片转成内联后会比原来大约三分之一，上限 24 MB | 改用「打印 / 存为 PDF」 |
| 点「打印 / 存为 PDF」没反应 | iOS 17.4 之前对打印有用户手势要求，或开了弹窗拦截 | 已修（不再延迟调用）；若仍无反应，走浏览器分享面板里的「打印」 |
| 导出后跳到文件界面，回不去 | 曾经是把当前标签导航到下载地址 | 已修：改用 `<a download>`，页面留在原处 |
| 下载链接打开显示「已经过期」 | 导出物只在服务端内存里放 5 分钟 | 回阅读页重新点一次 |
| 删了源文件，平台里还在 | 有意为之，删除源文件不影响库 | 要真删就在阅读页点「删除」 |
| 删掉的文档重启后又回来了 | 删除时勾了「以后还收」 | 重删一次，别勾那个选项 |
| 改名又改内容，结果多出一篇 | 内容变了，认不出是同一篇 | 手动删掉旧的那篇 |
| 服务停着时改的文档没进来 | 完整扫描只在启动时做一次 | 重启 `pe serve` 会补齐 |
| 监听 NFS / SMB 目录完全没反应 | 网络文件系统不产生 inotify 事件 | 改用 hook 或 `pe push` 推送模式 |
| 文档更新后又变回未读了 | 有意为之：有新版本 = 有新东西可读 | —— |
| iOS 上长按选中文字后点不到批注按钮 | 系统菜单画在选区旁边，网页盖不住 | 已修：触屏上气泡改到选区另一侧，并让开系统菜单的高度 |
| 改了程序但手机上没变化 | 浏览器缓存着旧前端 | 开 `#/diag` 看两个版本号；不一致就点「清缓存并重载」 |
| 气泡被地址栏或键盘挡住 | iOS 15 起 Safari 地址栏在屏幕底部 | 已修：按 visualViewport 的可见区域夹紧，不是按 innerHeight |
| 屏幕上没有选中标记，气泡却弹出来了 | iOS 长按会先产生一个临时选区再收掉 | 已修：连续两次读数一致才显示气泡，临时选区不会触发 |
| 点气泡上的按钮，气泡先自己消失了 | iOS 点按钮会发一个「什么也没说明」的选区事件 | 已修：这种事件不再被当成「选区没了」 |
| 划词划到已有高亮上，弹出的是批注卡片 | 拖拽结束后浏览器照样派发 click | 已修：手上还有选区时不当作点击 |
| 划词后气泡迟一下才出现 | 触屏上要先确认选区稳定（约 180ms） | 有意为之：不确认就会出现幽灵气泡 |
| 库里混进一堆不认识的 README / doxygen 页 | 监听根里有 vendored 依赖或构建树 | 升级后重启即可，新的忽略规则会自动并入；已入库的旧记录留在原地 |
| 图片裂了 / 显示占位块 | 图片不在项目根目录内，或超过 24MB | 平台拒绝越界的引用，这是安全限制 |
| 图表只显示源码 | mermaid 渲染失败 | 浏览器控制台会有 `[pe] mermaid …` 的警告，按提示看 |
| 断网后打不开某篇 | 那篇没有联网打开过，不在离线缓存里 | 离线只能读之前打开过的 |
| 项目名叫「docs」 | 早期版本的归属判定 bug | 已修复；老数据需要 `rm -rf ~/.local/share/pe` 重来 |

日志：前台运行直接看终端；systemd 下 `journalctl --user -u pe -f`。

## 九、边界与注意事项

- **单用户设计。** 一个口令、一份阅读状态、批注没有归属人。多台设备可以同时在线，
  但看到的是同一份状态。不适合多人共用。
- **没有会话管理。** Cookie 存的就是口令本身，所以没法单独踢掉某台设备；
  换口令 = 所有设备一起掉线，且必须重启服务才生效。
- **源文件删了平台里不删**，这是「平台是文件系统下游」这条取舍的直接后果。
  要真删就在阅读页点「删除」，那会连批注和版本历史一起删掉，且不可撤销。
- **改名跟随认内容不认事件**：同时改了名字又改了内容就认不出来，会多一篇。
- **删除不回收 blob。** 文档没了，它引用的原文和图片还在 `blobs/` 里——
  同一份内容可能被别的文档共用，没有引用计数就删是数据损坏而不是省空间。
- **完整扫描只在启动时做一次**，运行中靠 inotify 增量。停机期间的改动要重启才发现。
- **局域网使用。** 走 http 明文，别把端口暴露到公网；远程访问用 Tailscale。
- **`/api/v1/asset/<sha>` 是按内容哈希寻址的**，知道哈希的人可以取到那份资源。
  哈希是 64 位十六进制，无法枚举，但这仍是一个「知道链接就能访问」的能力型 URL。
- **原样模式的 HTML 不能批注、正文不进全文检索。** 带脚本或图表的 HTML 会以原样模式
  渲染以保住交互，代价就是这个。
- **一条批注只归属一个段落**，跨段落的选区会被截到起始段末尾。
- **含公式或图表的段落**里，高亮会跳过公式/图表本身那一小段，文字部分不受影响。
- **批注重定位做不到 100%。** agent 大幅重写时一定会出现失联批注。对策是永不删除、
  保留原文快照、支持手动重挂——原文真的消失时任何算法都只能猜，猜错比找不到更糟。
- **blobs 目前只增不减**，没有自动回收。

## 十、命令速查

```bash
pe serve [--bind 0.0.0.0:8080] [--data <目录>]   启动服务
pe watch add <目录> [--project 名称] [--include '*.md']
pe watch list
pe watch rm <目录>
pe push <文件|-> [--project 名称] [--tag 标签]... [--title 标题] [--run 会话ID]
pe hook-install [--write]                       装 Claude Code hook
pe hook-ingest [--verbose]                      hook 的接收端，一般不手动调
pe mcp                                          以 MCP server 运行
pe token                                        换新口令并打印二维码（需重启 serve）
pe version
```

环境变量：`PE_DATA_DIR`（数据目录）、`PE_ENDPOINT` / `PE_TOKEN`（客户端）。
